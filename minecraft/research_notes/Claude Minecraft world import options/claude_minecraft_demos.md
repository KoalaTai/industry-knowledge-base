# Claude / LLM agents building in and playing Minecraft (2025 - late 2026): demos, videos, tooling, MC-Bench

Research date: 2026-11-02. Scope: public demos, videos, write-ups and open-source projects where Claude models (esp. Claude Fable 5.1 / Claude 5 family / Mythos / Opus 5.5) or Claude Code build in or play Minecraft, plus comparable LLM-agent projects and MC-Bench-style comparisons.

Important framing note that runs through everything below: the 2026 "Claude built Minecraft" material splits into two very different categories that titles routinely blur:
1. **Minecraft CLONES** - the model writes a voxel game from scratch (usually a single HTML/three.js file or a Rust/terminal game). The model never touches real Minecraft. Most Fable 5 / Fable 5.1 / Mythos / Opus 5.5 "Minecraft" virality is this category.
2. **Building INSIDE real Minecraft** - a bot/plugin/MCP server lets the model place blocks in a running Java Edition world. This is the category relevant to world import, and it is almost entirely community tooling (Mineflayer bots, Paper/Fabric plugins with an MCP bridge, WorldEdit .schem generation, or macOS computer-use with screenshots + keystrokes).

Release-date anchors used to date everything (from Wikipedia's Claude Mythos article): Claude Mythos Preview disclosed 2026-04-07 (Project Glasswing, gated); Claude Opus 4.8 announced 2026-05-28; Claude Mythos 5 and Claude Fable 5 released 2026-06-09; Claude Fable 5.1 and Mythos 5.1 released 2026-09-01; Mythos 5.1 widened to Cyber Verification Program users 2026-10-06 - [Wikipedia: Claude Mythos](https://en.wikipedia.org/wiki/Claude_Mythos). Opus 5 / Opus 5.5 / Sonnet 5.5 dates were not stated in that article (see Gaps).

## Key Question 3: What is MC-Bench (mcbench.ai), how does it have models generate builds, and which Claude models lead as of late 2026?

### Takeaway
MC-Bench is a human-vote, pairwise, Elo-style benchmark (built by then high-schooler Adi Singh, early 2025) in which models write code that is executed on containerised Minecraft servers and the resulting builds are shown to voters; the last verifiable leaderboard snapshot (March 2025) had Claude 3.7 Sonnet #1 and Claude 3.5 Sonnet #2. The live late-2026 leaderboard could not be retrieved (JS-rendered), the GitHub org shows little activity after Sep 2025, and newer spin-off sites (MineBench, VoxelBench) use a raw JSON block-coordinate format instead.

### Cited Findings
- MC-Bench: "a head-to-head comparison where models generate Minecraft builds from a prompt"; built by high-school senior Adi Singh; users vote on which build is better and only then see which model made each; "since the models write code to produce the builds, MC-Bench is technically a programming benchmark" - [TechCrunch](https://techcrunch.com/?p=2982775), [AutoGPT](https://autogpt.net/high-schooler-builds-website-for-ai-minecraft-battles/)
- Leaderboard as of ~15 March 2025: #1 Claude 3.7 Sonnet, #2 Claude 3.5 Sonnet, #3 GPT-4.5 Preview; over 10,000 build samples voted on - [favtutor](https://favtutor.com/articles/mc-bench-minecraft-ai-models/), [thecodinglove](https://thecodinglove.com/this-site-pits-ais-against-each-other-to-build-minecraft-models)
- Ethan Mollick (Bluesky) flagged it as a favourite "weird AI benchmark" - [Bluesky](https://bsky.app/profile/emollick.bsky.social/post/3lkp4wrjcg22d)
- GitHub org "Minecraft AI Benchmark (mcbench.ai)" has 11 repos: mc-bench-backend (Python, last updated Sep 30, 2025), mc-bench-frontend (TypeScript, Apr 20, 2025), gameservers / mc-data-files / mc-assets (Jan 15, 2025), a fork of PrismarineJS/prismarine-viewer "Web based viewer for servers and bots" (Jan 15, 2025), mc-bench-infrastructure (HCL, Dec 2024), builder-base-container ("A base container for the minecraft builder", Dec 2024), orchestrator ("Worker to orchestrate and manage running an arbitrary number of LLM-generated builds" on "containerized Minecraft Servers", Dec 2024), simple-minecraft-server-builder (JS, Nov 2024) - [github.com/mc-bench](https://github.com/mc-bench)
- mc-bench-backend architecture diagram: an Admin Worker connects to model providers (OpenAI, Anthropic, Gemini, Mistral, Grok, Other); a Server Worker and a "Builder Runner" connect to "Minecraft Servers"; a "Render Worker" exists; Celery workers via Redis, PostgreSQL + object storage - [architecture.md](https://github.com/mc-bench/mc-bench-backend/blob/main/docs/technical-details/architecture.md). The README says only that MC-Bench challenges models "to create Minecraft builds" and points to a Docker Quick Start and Architecture Guide - [mc-bench-backend](https://github.com/mc-bench/mc-bench-backend)
- MineBench (minebench.ai), "Inspired by MC-Bench and VoxelBench": models read a text prompt and output JSON `{version, blocks:[{x,y,z,type}]}` with block types like `oak_log`/`stone` (example build 1,247 blocks); "no images or 3D tools"; coordinates rendered directly with "Faithful" textures; pairwise human votes feed a live Elo leaderboard; home page showed only three entries: #1 GPT-5.4 (2150), #2 "Claude 4.5" (2108), #3 Gemini 3 Pro (2091); no dates shown - [minebench.ai](https://minebench.ai/)
- MineBench has a model profile page for Claude Opus 5 listing 15 prompts, score range "100% -> 72.9%", strongest result "A skyscraper," and head-to-head records including Opus 5 vs Claude Opus 5.5 - [minebench.ai/leaderboard/opus-5](https://minebench.ai/leaderboard/opus-5). The full /leaderboard page returned only "Loading leaderboard" - [minebench.ai/leaderboard](https://minebench.ai/leaderboard)
- A separate "minebench" repo exists at github.com/pst2154/minebench (contents not examined) - [GitHub](https://github.com/pst2154/minebench)
- General (non-Minecraft) late-2026 leaderboards place Claude Opus 5.5 first on coding/agentic indices with Claude Fable 5.1 second on agentic (80.7) - [benchlm.ai/agentic](https://benchlm.ai/agentic), [benchleader.com](https://www.benchleader.com/)

### Inferences
- From the repo set (builder-base-container, orchestrator running "LLM-generated builds" on containerised servers, a prismarine-viewer fork, a Render Worker), the MC-Bench pipeline is: model emits a build *program* -> executed by a "builder" container against a real Minecraft server -> the region is exported and rendered in a Prismarine/three.js-style web viewer for pairwise voting. My recollection from training data is that the program is JavaScript using a small block-placement API (safeSetBlock/safeFill-style) rather than Mineflayer movement, but I could not confirm the exact language/API from the fetched pages, so treat that detail as unverified.
- Repo activity ending Sep 2025 plus the rise of MineBench/VoxelBench suggests MC-Bench itself may not have been updated with Claude 5-family models; a late-2026 "Claude leads MC-Bench" claim could not be substantiated either way.

### Gaps
- mcbench.ai/leaderboard and /about are client-rendered; fetch returned empty. The late-2026 MC-Bench standings (and whether Fable 5.1 / Opus 5.5 are even on it) are unknown. Recommend loading mcbench.ai in a browser.
- The exact prompt/output contract (language, API surface, size limits) of MC-Bench was not found in the README or architecture doc; it is in the source under `src/mc_bench` which was not read.
- MineBench's full leaderboard (beyond the top-3 teaser) failed to load; "Claude 4.5" there is ambiguous (Opus 4.5 vs Sonnet 4.5).

## Key Question 4: Mindcraft, Voyager, and other open-source LLM-in-Minecraft agents - do they support Claude, and what do they use under the hood?

### Takeaway
Mindcraft (kolbytn, ~6.0k stars) is the dominant open-source LLM-in-Minecraft agent; it is built on Mineflayer, supports Anthropic/Claude as one of ~17 providers (via ANTHROPIC_API_KEY, with code execution off by default), and targets Java Edition up to 1.21.11. Voyager (NVIDIA/MineDojo) is GPT-4-only officially; Claude support exists only in a community fork. A 2026 wave of Claude-specific projects (ClaudeCraft x2, Claudecraft/Agent SDK, AgentCraft, minecraft-use) layers Claude Agent SDK / Claude Code on top of Mineflayer or Fabric mods.

### Cited Findings
- **Mindcraft** (kolbytn/mindcraft): "Crafting minds for Minecraft with LLMs and Mineflayer"; MIT; ~6.0k stars, 985 forks, 1,673 commits on `develop`; ~17 providers incl. OpenAI, Gemini, Anthropic, xAI, DeepSeek, Mistral, Groq, OpenRouter, Ollama; README examples name `gpt-5.4`, `gpt-5.4-mini`, `gemini-2.5-pro` but no specific Claude model (older README example was `claude-3-haiku-20240307`); Java Edition up to 1.21.11 (1.21.6 recommended), Node 18/20; coding disabled by default (`allow_insecure_coding`), "Do not connect this bot to public servers with coding enabled"; separate `code_model` and `vision_model`; finetuned local "Andy-4" models via Ollama; MineCollab multi-agent; arXiv paper 2504.17950 - [GitHub](https://github.com/kolbytn/mindcraft), [search summary](https://github.com/kolbytn/mindcraft)
- **Voyager** (MineDojo/Voyager): built around GPT-4, requires an OpenAI key; "strictly for research purposes, not an official NVIDIA product" - [GitHub](https://www.github.com/MineDojo/Voyager), [arXiv 2305.16291](https://arxiv.org/abs/2305.16291). Community fork JVP15/Voyager-LLM-Trials adds other LLMs; author reports that other than GPT-4 they did "not well"; Claude 3.5 Sonnet best of the Claude models, Claude 3 Sonnet "doesn't go much farther than mining wood"; Claude accessed via Vertex AI, paired with OpenAI embeddings because Claude has no embedding model - [GitHub](https://github.com/JVP15/Voyager-LLM-Trials)
- **ClaudeCraft (louz514/Claudecraft)**: three Claude-powered bots (Claude_Explorer, Claude_Builder, ClaudeAdventurer) on Mineflayer + Paper MC 1.21.4, TypeScript/Node, BlueMap web viewer, pm2, Cloudflare tunnels; model `claude-sonnet-4-20250514`; Claude API call every ~10 s (autonomous) / 12 s (survival), ~950 tokens per decision, ~360 calls/hour; up to 500 memories per agent plus shared world memory; HTTP API (8081) accepts build requests ("Build a medieval tower"), WebSocket log stream (8080); builds castles/buildings in creative mode; Colosseum hackathon deadline 2026-02-12; also promotes a Solana token ($CRAFT) with wagering - [GitHub](https://github.com/louz514/Claudecraft)

- **AgentCraft** (Blendi, early Oct 2026): "a multi-agent harness that runs inside Minecraft. A team of Claude agents plans, builds in real worktrees, and walks over when they need you" - [x.com/BlendiByl](https://x.com/BlendiByl/status/2106226258984264042); AlphaSignal/hermes-ai write-up (2026-10-08): open-source Fabric mod, "walkable Minecraft studio," git worktrees, in-game diffs, merge gating; agents represent *coding* work, no statement that they build structures - [hermes-ai.net](https://hermes-ai.net/news/agentcraft-turns-minecraft-into-a-live-claude-coding-agent-control-room/)

### Inferences
- Under the hood, nearly every in-game Claude agent is Mineflayer (a Node.js headless client that joins as a player): Mindcraft, ClaudeCraft (both), haksnbot, yuniko MCP. The alternatives are (a) server-side plugin/mod with an HTTP/WebSocket bridge (MairwunNx WorldAPI, IotA-asce Paper bridge, AgentCraft Fabric) and (b) screenshot+keystroke computer-use, which the two computer-use repos both describe as latency- and precision-limited.

## Key Question 5: Community write-ups of Claude Code + an MCP server building cities/landmarks in Minecraft - what worked, what broke?

### Takeaway
There are at least six open-source Minecraft MCP servers that Claude Code can drive (Mineflayer-based: yuniko, haksnbot; plugin/mod-bridge-based: MairwunNx WorldAPI, IotA-asce Paper bridge, chapmanjw Fabric plugin; offline schematic generators: joshdevous, minecraft-schematic-lab). The best-documented landmark demos are yuniko's Eiffel Tower / White House builds; documented failure modes are Minecraft-version lock-in (1.21.11), LAN/open-world prerequisites, MCP not triggering unless the prompt names Minecraft, latency, and (for computer-use) imprecise coordinates. No long-form "Claude Code built a city" post-mortem was found.

### Cited Findings
- **yuniko-software/minecraft-mcp-server** (Apache-2.0, 807 stars, 105 forks, 220 commits): Mineflayer bot joins as a player (singleplayer: open to LAN on 25565; `--host/--port/--username`); supports Minecraft 1.21.11 ("Newer versions may not work"; prerequisites section says tested on 1.21.8); tools: get-position, move-to-position, look-at, jump, move-in-direction, fly-to, list-inventory, find-item, equip-item, place-block, dig-block, get-block-info, find-blocks, smelt-item, find-entity, send-chat, read-chat, detect-gamemode; Claude Desktop documented, "other MCP clients also supported"; README embeds "minecraft-mcp-server-white-house.mp4"; limitations: world must be open to LAN first, Claude Desktop slow to start the server and needs full restart, prompt must explicitly ask for a Minecraft action or the MCP won't trigger - [GitHub](https://github.com/yuniko-software/minecraft-mcp-server). The author's site post is titled "Claude's building the Eiffel Tower in real-time - powered by my custom Minecraft MCP Server" (site had a TLS cert error on fetch) - [yuniko.software](https://yuniko.software/mcp-server/)
- **MairwunNx/minecraft-mcp** (MIT, TypeScript, npm `@mairwunnx/minecraft-mcp`, 133 commits): MCP bridge to a separate "WorldAPI" (>=4.2.0) server-side mod/plugin for Paper, Fabric or NeoForge exposing REST + WebSocket; 51 tools (server, worlds, blocks, chests, entities, players, commands, leaderboards, recipes, configs, logs, Java scripts); explicit Claude Code support via `claude mcp add minecraft` with `WORLDAPI_URL`/`WORLDAPI_TOKEN`; Claude Desktop via `.mcpb` bundle; read-only "viewer token" (19 tools); live event notifications; Discord/Telegram/Slack webhooks; **undo feature for agent-made builds**; live public demo server "Moonlands"; Node 22+ required - [GitHub](https://github.com/MairwunNx/minecraft-mcp), [Claude Code wiki](https://github.com/MairwunNx/minecraft-mcp/wiki/Claude-Code)

- **haksndot/haksnbot-tools**: Mineflayer + mineflayer-pathfinder + prismarine-viewer + MCP SDK, 40+ bot tools incl. building and `take_screenshot` (needs OpenGL/Mesa); Claude Code setup documented; part of a four-repo suite (mind/admin/memory); 3 stars, 46 commits; no demos - [GitHub](https://github.com/haksndot/haksnbot-tools)
- **chapmanjw/minecraft-java-fabric-claude-plugin**: MCP server embedded in a Fabric mod for Java Edition, plus a Claude Code plugin with skills and a "builder agent" - [GitHub](https://github.com/chapmanjw/minecraft-java-fabric-claude-plugin)
- **joshdevous/minecraft-builder-claude-mcp-server**: converts natural-language descriptions into WorldEdit-compatible `.schem` files "without API costs"; Minecraft 1.13+, WorldEdit 7.x for import - [GitHub](https://github.com/joshdevous/minecraft-builder-claude-mcp-server), [LobeHub listing](https://lobehub.com/mcp/joshbker-minecraft-builder-claude-mcp-server)
- **simonerecchia/minecraft-schematic-lab**: MCP server letting Claude "build, preview and export WorldEdit Sponge .schem schematics" to paste into a world - [GitHub](https://github.com/simonerecchia/minecraft-schematic-lab)
- **MCDxAI/minecraft-dev-mcp**: MCP server for Minecraft *mod development* (not in-game building) - [GitHub](https://github.com/MCDxAI/minecraft-dev-mcp)

- Computer-use failure modes: ObservedObserver reported coordinate control "not accurate enough" and inability to handle complex multi-step tasks without careful prompting - [GitHub](https://github.com/ObservedObserver/claude-minecraft-use); SauersML's repo notes real-time play is latency-bound and so leans on typed chat commands (`/fill`, `/tp`) - [GitHub](https://github.com/SauersML/claude-plays-minecraft)

### Inferences
- For importing or generating large structures, the community has converged on three patterns, in rough order of robustness: (1) offline `.schem` generation + WorldEdit/Litematica paste (joshdevous, schematic-lab, minecraft-use) - deterministic, no server coupling; (2) server-side plugin/mod bridge with bulk block APIs and undo (MairwunNx WorldAPI, IotA-asce Paper bridge) - fast, works without a player; (3) Mineflayer player-bot (yuniko, haksnbot, Mindcraft, ClaudeCraft) - most "demo-able" on video but one-block-at-a-time, version-locked and reliant on pathfinding.
- The IotA-asce repo's approach of having Claude Code write TypeScript "build scripts" (castle, bridge, megastructure) that the harness executes is the closest open analogue to the MC-Bench "model emits a build program" pattern.

### Gaps
- No Reddit/blog post-mortem titled along the lines of "Claude Code built a city in Minecraft, here's what broke" was found despite a targeted search; the only failure detail comes from READMEs.
- yuniko's Eiffel Tower blog post could not be read (TLS error), so which Claude model/client and what broke in that build are unknown.
- Star counts/last-update dates were visible for only some repos; recency of MairwunNx, IotA-asce and chapmanjw projects relative to Nov 2026 is unverified.
