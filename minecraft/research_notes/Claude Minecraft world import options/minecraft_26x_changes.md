# Minecraft Java Edition 1.21.x to 26.x: changes affecting datapacks, functions, game rules and world saves

Research date: 2026-11-02. Java Edition only. Primary source throughout is the Minecraft Wiki (minecraft.wiki), which transcribes Mojang's official changelogs; third-party sources are flagged as such.

## Key Question 1: Versioning — when did Mojang switch to year-based versions, cadence, current release and latest snapshot

### Takeaway
Java Edition moved from 1.21.x to a `YY.D.H` (year.drop.hotfix) scheme with 26.1, whose first snapshot shipped December 16, 2025 and whose full release was March 24, 2026. As of early November 2026 the current full release is 26.3 "Wilderness Bound" (September 15, 2026), and the latest development build is 26.4 Snapshot 6 (October 27, 2026); 26.4 "Fourth Drop 2026" is the upcoming release, implying roughly quarterly drops.

### Cited Findings
- 26.1 is "the first Java Edition release using the 'year.drop.hotfix' format, which the page says was announced in December 2025." Release date March 24, 2026; data version 4786; protocol 775; Java SE 25 is the minimum (first version requiring it); 11 snapshots, 3 pre-releases, 3 release candidates. — [Minecraft Wiki, Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- Release table (development start / full release): 26.1 — Dec 16, 2025 / Mar 24, 2026; 26.1.1 — Mar 31, 2026 / Apr 1, 2026; 26.1.2 "Tiny Takeover" — Apr 8, 2026 / Apr 9, 2026; 26.2 "Chaos Cubed" — Apr 7, 2026 / Jun 16, 2026; 26.3 "Wilderness Bound" — Jun 23, 2026 / Sep 15, 2026; 26.4 "Fourth Drop 2026" — listed as upcoming, Q4 2026 (the table's Sep 22, 2026 date for 26.4's first development release is flagged by the fetch as ambiguous). — [Minecraft Wiki, Java Edition version history](https://minecraft.wiki/w/Java_Edition_version_history)
- Scheme description from server-host documentation: "From 2026 onwards, Java Edition releases are numbered YY.D.H, where the first number is the year, the second is the drop, and the third is the hotfix." Bedrock uses a different counter (Java 26.1 ≈ Bedrock 26.10). — [GameServerKings knowledge base](https://www.gameserverkings.com/knowledge-base/minecraft/updating-your-server-version/) (third-party)
- 26.2 "Chaos Cubed": released June 16, 2026; data version 4903; protocol 776; 8 snapshots, 6 pre-releases, 2 RCs. — [Minecraft Wiki, Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- 26.3 "Wilderness Bound": released September 15, 2026; data version 5023; protocol 777; 10 snapshots, 3 pre-releases, 3 RCs. — [Minecraft Wiki, Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)
- Development-version list: 26.3 Snapshots 1–10, 26.3-pre-1..3, 26.3-rc-1..3; 26.4 Snapshots 1–6; "Latest snapshot named on the page: 26.4 Snapshot 6." — [Minecraft Wiki, Development versions](https://minecraft.wiki/w/Java_Edition_version_history/Development_versions)
- 26.4 Snapshot 6: released October 27, 2026; data pack format 125.1; resource pack format 101.0; data version 5126. — [Minecraft Wiki, Java Edition 26.4 Snapshot 6](https://minecraft.wiki/w/Java_Edition_26.4_Snapshot_6); release date corroborated by [DoomHosting](https://www.doomhosting.com/minecraft-server-download/snapshot/26.4-snapshot-6) (third-party)
- Snapshot naming also changed: builds are now named "26.1 Snapshot 1", "26.3-pre-1", "26.3-rc-1" rather than the old `25w44a` style; the last old-style snapshots (25w31a…25w46a) belong to 1.21.9–1.21.11. — [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format)
- Third-party date for 26.3 Snapshot 6: July 28, 2026 (data pack format 113.0). — [IronCrest-sudo/upgrader README](https://github.com/IronCrest-sudo/upgrader)

### Inferences
- Four named drops in 2026 (26.1 through 26.4) means roughly one drop per quarter, each with hotfix releases (26.1.1, 26.1.2) as needed. The wiki does not state the cadence explicitly; this is inferred from the table and the "Fourth Drop 2026" name.
- The last 1.x release was 1.21.11 (data pack format 94.1), so "1.21 or newer" targeting must cover 1.21 → 1.21.11 → 26.1 → 26.3 (and 26.4 shortly).

### Gaps
- Exact release dates for each individual 26.1/26.2/26.3 snapshot, pre-release and RC were not captured (the wiki's development-versions page lists names without dates in the fetched portion).
- Mojang's official announcement article for the versioning change was not fetched directly; the wiki and third-party coverage agree on the facts above.

## Key Question 2: pack.mcmeta — pack_format for 26.3, min_format/max_format, legacy `pack_format` + `supported_formats`

### Takeaway
26.3 uses data pack format **121.0** (resource pack 97.1); 26.1 is 101.1, 26.2 is 107.1, and the current 26.4 Snapshot 6 is 125.1. Since 25w31a (1.21.9) the schema uses required `min_format`/`max_format` (integer or `[major, minor]`), `supported_formats` was removed, and `pack_format` is optional; both legacy fields are allowed only when a pack also claims support for formats below 82. A pack declaring only `pack_format: 48` with `supported_formats.max_inclusive: 999` is therefore a "legacy-era" declaration — no source confirms it loads cleanly on 26.3, and a 25w31a-era pack author reported an "incompatible" display in that situation.

### Cited Findings
- Release data pack formats: 48 (1.21–1.21.1), 57 (1.21.2–1.21.3), 61 (1.21.4), 71 (1.21.5), 80 (1.21.6), 81 (1.21.7–1.21.8), 88.0 (1.21.9–1.21.10), 94.1 (1.21.11), 101.1 (26.1–26.1.2), 107.1 (26.2), 121.0 (26.3). Resource pack: 69.0 (1.21.9–10), 75.0 (1.21.11), 84.0 (26.1), 88.0 (26.2), 97.1 (26.3). — [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format)
- Development data pack formats: 25w31a 82 … 25w44a 92 … 1.21.11 94.1; 26.1 Snapshot 1–11: 95, 96, 97, 97.1, 98, 99, 99.1, (S8 n/a), 99.2, 99.3, 100; 26.2 S2–S8: 101.2, 102, 103, 104, 105, 105.1, 106; 26.2 Pre-1 106.1, Pre-3 group 107, 26.2 107.1; 26.3 S1–S10: 108, 109, 110, 111, 112, 113, 115, 116, 117, 118; 26.3 Pre-1 119; RC/Pre-2 group 120; 26.3 121; 26.4 S1–S6: 122, 122.1, 123, 124, 125, 125.1. — [Minecraft Wiki, Pack format (development table)](https://minecraft.wiki/w/Pack_format)
- "The minor-version scheme starts with 82.0 (25w31a)"; "Starting with 1.21.9, format values include a minor part (for example 88.0, 94.1, 121.0). Minor numbers increase for non-breaking changes." — [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format); [Minecraft Wiki, Data pack](https://minecraft.wiki/w/Data_pack)
- 25w31a schema change: "The `supported_formats` field has been removed. It is still required only if the pack supports pack versions below data pack 82 or resource pack 65. Otherwise it is not allowed and must be removed." `pack_format` "remains required only for packs that support pack versions below data pack 82 or resource pack 65." `min_format` and `max_format` "are required in the `pack` section and in overlay entries." — [Minecraft Wiki, Java Edition 25w31a](https://minecraft.wiki/w/Java_Edition_25w31a)
- Value forms: "A single integer is read as that major version with minor 0 (`74` = `[74, 0]`). A full version is a two-integer list, such as `[74, 1]`. A single-element list such as `[74]` is treated the same as the integer `74`. For `max_format`, a single integer means any minor version (the minor version is `0x7fffffff`)." Overlays: the `formats` field is removed (allowed only if an overlay range includes a version below 82) and overlays use `min_format`/`max_format`. — [Minecraft Wiki, Java Edition 25w31a](https://minecraft.wiki/w/Java_Edition_25w31a)
- Wiki's current example pack.mcmeta writes both fields as arrays, e.g. `"min_format": [88, 0], "max_format": [88, 0]`; the Pack format article recommends `"min_format": 88, "max_format": 88` for 1.21.9+. — [Minecraft Wiki, Data pack](https://minecraft.wiki/w/Data_pack); [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format)
- Compatibility display: "If a pack's format number is higher than the game supports, the pack appears as 'incompatible.'" If the number "does not match the game's supported format, Minecraft displays a warning in the pack list." The article does not give the warning text or state whether mismatched packs still load. — [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format)
- Error text when legacy overlay `formats` is present on a pack whose range is ≥82: "key formats is deprecated starting from pack format 82. Remove formats from your pack.mcmeta." (MC-302593, open/confirmed, affects 1.21.9–1.21.10; a pack with `supported_formats: [71, 88]`, `pack_format: 71`, `min_format: 71`, `max_format: 88` plus an overlay with `formats` failed to load in 1.21.9 but validated once `formats` was removed.) — [Mojira MC-302593](https://mojira.dev/MC-302593)
- Data-pack author note for 25w31a: a "broken or incompatible" error is displayed when selecting the pack in the New World screen "though the pack should still work." — [Modrinth, Better Unpackables v3.0.0-beta1 changelog](https://modrinth.com/datapack/better-unpackables/version/v3.0.0-beta1) (third-party, anecdotal)
- Pre-1.21.9 history: `supported_formats` was added in 23w31a (1.20.2, format 18) as "an optional field … which describes a range for pack formats that this pack supports." — [Minecraft Wiki mirror, Pack format](https://wiki.ronlab.site/content/minecraftwiki_en_all_maxi_2025-11/Pack_format)
- Third-party tool corroboration of release numbers: mcpack lists 101.1 for 26.1–26.1.2 and 107.1 for 26.2. — [docs.rs mcpack 0.3.0](https://docs.rs/crate/mcpack/0.3.0)

### Inferences
- A generator targeting "1.21 or newer" that wants to span both eras should emit **all** of: `pack_format: 48`, `supported_formats: {"min_inclusive": 48, "max_inclusive": <high>}`, and `min_format: 48`, `max_format: [<current major>, 0x7fffffff]` or a plain integer such as `max_format: 125` (plain integer on max_format = any minor). Per 25w31a, legacy fields are permitted precisely because the range starts below 82; the new fields are "required", so omitting them is the risky configuration.
- Because the content folders, predicate schema, loot/number-provider schema and game-rule IDs changed incompatibly between 48 and 121, a single pack cannot truthfully support 48 through 121 without overlays; honest practice is to generate separate outputs per era, or use `overlays` with `min_format`/`max_format` entries.
- Nothing in the sources says a format mismatch blocks loading via `/datapack enable` or on `/reload`; the wiki only documents a warning/"incompatible" label in the pack-selection UI. Treat "loads with warning" as likely but unverified for 26.3.

### Gaps
- No source states the exact runtime behaviour on 26.3 of a pack.mcmeta that has `pack_format` + `supported_formats` but **no** `min_format`/`max_format` (whether the game synthesises a range from the legacy fields, warns, or refuses). This needs an empirical test on 26.3.
- The exact "incompatible" warning string in the current UI was not found.
- The official minecraft.net 25w31a article could not be fetched (search returned only third-party pages); the wiki transcription was used.

## Key Question 3: Game rules — camelCase to namespaced snake_case rename

### Takeaway
In snapshot 25w44a (a 1.21.11 snapshot, late 2025) every game rule became a registry entry addressed by a namespaced snake_case ID (e.g. `maxCommandChainLength` → `minecraft:max_command_sequence_length`); some rules were renamed semantically, three had their boolean meaning inverted, `doFireTick`/`allowFireTicksAwayFromPlayer` were replaced by an integer rule, and minimum/maximum bounds were added. No source documents old names being accepted as aliases, and a community mod exists specifically to restore them, which strongly implies old names fail.

### Cited Findings
- "The rename happened in Java snapshot 25w44a (Java 1.21.11). The page says: 'All game rules have now been moved into a registry.' Rules were renamed to snake_case resource locations, and some values were inverted." — [Minecraft Wiki, Game rule](https://minecraft.wiki/w/Game_rule)
- Explicit rename table in 25w44a (old → new, all under the `minecraft:` namespace): announceAdvancements → show_advancement_messages; commandBlocksEnabled → command_blocks_work; command_modification_block_limit → max_block_modifications; disableElytraMovementCheck → elytra_movement_check (inverted); disablePlayerMovementCheck → player_movement_check (inverted); disableRaids → raids (inverted); doDaylightCycle → advance_time; doEntityDrops → entity_drops; doImmediateRespawn → immediate_respawn; doInsomnia → spawn_phantoms; doLimitedCrafting → limited_crafting; doMobLoot → mob_drops; doMobSpawning → spawn_mobs; doPatrolSpawning → spawn_patrols; doTileDrops → block_drops; doTraderSpawning → spawn_wandering_traders; doVinesSpread → spread_vines; doWardenSpawning → spawn_wardens; doWeatherCycle → advance_weather; maxCommandChainLength → max_command_sequence_length; maxCommandForkCount → max_command_forks; naturalRegeneration → natural_health_regeneration; snowAccumulationHeight → max_snow_accumulation_height; spawnRadius → respawn_radius; spawnerBlocksEnabled → spawner_blocks_work. — [Minecraft Wiki, Java Edition 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a)
- Rules whose IDs are only a mechanical snake_case conversion are not in the rename table but appear under their new names elsewhere on the wiki: `keep_inventory`, `mob_griefing`, `fall_damage`, `random_tick_speed`, `players_sleeping_percentage`, `max_entity_cramming`, `spectators_generate_chunks`. — [Minecraft Wiki, Game rule](https://minecraft.wiki/w/Game_rule); [Minecraft Wiki, Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2) (uses `spectators_generate_chunks`); [Minecraft Wiki, Java Edition 26.4 Snapshot 6](https://minecraft.wiki/w/Java_Edition_26.4_Snapshot_6) (uses `mob_griefing`)
- Third-party reference listing `max_command_sequence_length | Integer | 65536 | maxCommandChainLength` and describing the broader rename as 25w44a. — [minecraftmaps.com gamerules reference](https://www.minecraftmaps.com/tools/gamerules-reference) (third-party)
- Fire rules: "`doFireTick` and `allowFireTicksAwayFromPlayer` were removed and replaced by `minecraft:fire_spread_radius_around_player`. A value of `0` disables fire spread, `-1` allows spread with no players nearby, and the minimum is `-1`." — [Minecraft Wiki, Java Edition 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a)
- New bounds in 25w44a: minimums for max_block_modifications (1), max_command_forks (1), max_command_sequence_length (0), max_entity_cramming (1), max_snow_accumulation_height (0, max 8), players_nether_portal_creative_delay (0), players_nether_portal_default_delay (0), players_sleeping_percentage (0), random_tick_speed (0), respawn_radius (0). — [Minecraft Wiki, Java Edition 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a)
- Earlier related changes: `spawnChunkRadius` removed in 25w31a (fixed spawn chunks removed; forceloaded chunks still preload); `enableCommandBlocks` → `commandBlocksEnabled` in 25w37a, then → `command_blocks_work` in 25w44a. — [Minecraft Wiki, Java Edition 25w31a](https://minecraft.wiki/w/Java_Edition_25w31a); [Minecraft Wiki, Game rule](https://minecraft.wiki/w/Game_rule)
- The Function page now describes the per-function limit as "/gamerule max_command_sequence_length," default 65,536; commands beyond the limit are ignored. — [Minecraft Wiki, Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Community mod "Classic Gamerule" exists to restore the old names as aliases; its author states Minecraft "renamed all gamerules from camelCase to namespaced:snake_case in 25w44a (1.21.11 snapshot), and even reverted the values of some rules, which broke all existing usage of gamerules." — [CurseForge, Classic Gamerule](https://www.curseforge.com/minecraft/mc-mods/classic-gamerule) (third-party)
- 26.1 UI: game rules screen reachable in-game via a new World Options screen; search bar added. 26.2: respawning as spectator in Hardcore no longer turns off `spectators_generate_chunks`. — [Minecraft Wiki, Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki, Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- A server-host blog claims the switch came in 25w35a and ties it to 26.2; this conflicts with the wiki's 25w44a and is treated as wrong. — [xgamingserver blog](https://xgamingserver.com/blog/?p=22921) (third-party, contradicted by [Minecraft Wiki, Game rule](https://minecraft.wiki/w/Game_rule))

### Inferences
- Mapping for the three rules the generator most likely emits (not in the explicit rename table because the change is purely mechanical): `commandBlockOutput` → `minecraft:command_block_output`, `sendCommandFeedback` → `minecraft:send_command_feedback`, `logAdminCommands` → `minecraft:log_admin_commands`, `keepInventory` → `minecraft:keep_inventory`, `mobGriefing` → `minecraft:mob_griefing`, `randomTickSpeed` → `minecraft:random_tick_speed`, `showDeathMessages` → `minecraft:show_death_messages`, `reducedDebugInfo` → `minecraft:reduced_debug_info`. The wiki confirms the snake_case forms for keep_inventory, mob_griefing, random_tick_speed and spectators_generate_chunks; the others follow the stated "all game rules … snake-case resource locations" rule but were not individually verified.
- `/gamerule` takes the rule as a literal node in the command tree, so a function line like `gamerule maxCommandChainLength 1000000` will not parse on 1.21.11+ and, per the function-loading rule in Question 4, will cause the whole .mcfunction to fail to load. The generator should emit `gamerule max_command_sequence_length …` (the `minecraft:` prefix is optional for namespaced IDs by convention) for format ≥ 92 and the camelCase name for format < 92.
- Semantics to watch when migrating: `disableRaids true` becomes `raids false`; `doFireTick false` becomes `fire_spread_radius_around_player 0`.

### Gaps
- No primary source states whether old camelCase names are accepted as aliases in `/gamerule`; the inference that they are rejected rests on the registry change and on the existence of the Classic Gamerule mod. Needs an in-game test.
- No source describes how existing worlds' `level.dat` GameRules were migrated into the new IDs (presumably a DataFixer in 25w44a / 26.1 Snapshot 6), nor whether `/gamerule` accepts the un-namespaced short form; standard registry-argument behaviour (default `minecraft:` namespace) is assumed.
- A complete authoritative list of every current rule ID with its exact old name was not captured; only the explicit 25w44a rename table plus the examples above.

## Key Question 4: Function loading behaviour on parse errors; /reload reporting

### Takeaway
If any line of a `.mcfunction` fails to parse, the whole function is not loaded; the detail ("Failed to load function … Whilst parsing command on line N") goes to the server/game log, and the wiki does not document any chat-side report from `/reload`. A long-standing Mojira ticket describes exactly this "silent" failure mode.

### Cited Findings
- "if any of the lines in a function file is unparseable, the function file cannot be loaded." "if function files are changed, use /reload to reload them from disk." The page does not say whether the error is logged, what message appears, or whether `/reload` shows errors in chat. — [Minecraft Wiki, Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Macro lines: parsed before each execution; "If a required variable is missing or a macro line can't be parsed, 'the entire function is not invoked and no commands in it run.'" `$` prefix, `$(key)` substitution (keys limited to letters/digits/underscores), strings inserted without quotes, numbers without type suffixes, booleans as 1/0; `function foo:bar2 with entity @s SelectedItem` form. — [Minecraft Wiki, Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Execution order: `#minecraft:load` runs on world load/server start and on data pack reload, before players join (so `@a`/`@p` selectors match nobody); `#minecraft:tick` at the start of every tick; since 1.19.3 `#load` runs before `#tick`; within a tick: advancement functions, enchantment functions, `#tick`, scheduled functions, then command blocks/players. Functions in a tag run in listed order, duplicates only once. — [Minecraft Wiki, Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Mojira MC-121768: "a function with a bad command fails on load or `/reload` without a clear message, and the server log is where the details appear"; a commenter notes "a function that errors isn't added to the loaded list, which is by design." — [Mojira MC-121768](https://mojira.dev/MC-121768)
- Example log line from a Paper server: `Failed to load function … Whilst parsing command on line N` triggered by a bad `gamerule` argument in a function. — [mclo.gs raw log rydMWKQ](https://api.mclo.gs/1/raw/rydMWKQ) (user-submitted log)
- Since 20w22a, a failed reload leaves the previous data in place; if a pack is corrupted/malformed, opening the world offers Safe Mode. — [Minecraft Wiki, Data pack](https://minecraft.wiki/w/Data_pack)

### Inferences
- For a Python generator this means: a single version-mismatched command (old game-rule name, JSON text component on a 26.x target, or `functions/` folder on 1.21+) silently drops the whole function; detection must come from grepping the game log for `Failed to load function` rather than from chat. In singleplayer the integrated server writes the same message into the client `latest.log`.

### Gaps
- The exact current (26.3) wording of the parse-failure log message was not verified against a 26.x log; the "Whilst parsing command on line" wording is from a 1.2x-era Paper log.
- Whether `/reload` in 26.x prints any error summary in chat (as opposed to only "Reloading!") is not documented in fetched sources.

## Key Question 5: Command changes since 1.21 relevant to generated scripts

### Takeaway
The biggest break is 1.21.5 (format 71): text components in `/tellraw`, `/title` etc. are SNBT instead of JSON, `/data` accepts heterogeneous lists, and `/fill`/`/setblock`/`/clone`/`/place template` gained `strict`. 1.21 (24w21a) made all data-pack folders singular (`function/`, `structure/`, `tags/function/`). 26.1 rebased `/time` on world clocks and added `/swing`, `/fetchprofile`; 26.2 added `/unpublish` and tightened colour names; 26.3 added `/compute` and `/posteffect`. No block-ID renames affecting `fill`/`setblock` were found in 26.1–26.4 S6.

### Cited Findings
- 1.21 (24w19a tags, 24w21a content): `structures` → `structure`, `recipes` → `recipe`, `loot_tables` → `loot_table`, `functions` → `function`, `tags/functions` → `tags/function`, `tags/items` → `tags/item`, etc.; shipped in 1.21 with pack format 48. — [Minecraft Wiki, Data pack](https://minecraft.wiki/w/Data_pack); [Minecraft Wiki, Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- 1.21.5 (format 71): text components in commands such as `/tellraw` and `/title` "are now specified with SNBT instead of JSON"; `/scoreboard` styled number format moved JSON → SNBT; `/bossbar`, `/scoreboard`, `/team` text arguments resolve in the context of `@s`. — [Minecraft Wiki, Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- 1.21.5: `/data` can create/modify heterogeneous lists and "can no longer traverse paths with an empty key"; inserting a different-typed element no longer errors; typed arrays `[I;…]` still restricted; on-disk NBT is unchanged — mixed lists are stored as wrapped compounds (`['a', {'b':3}]` becomes `[{'':'a'},{'b':3}]`), which "external tools will show." — [Minecraft Wiki, Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- 1.21.5: `/fill` `replace` is no longer terminal; new `strict` option on `/fill`, `/clone`, `/setblock`, `/place template` places blocks without block/shape updates; `/setblock`/`/fill` preserve existing block-entity data when none is specified, `{}` clears it; success if either state or data changes. Inline values (`/give`, `/loot`, `/tellraw`, `/execute if predicate`) accept numbers in place of booleans again. New `/test` command. — [Minecraft Wiki, Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- 25w31a (1.21.9): `/summon` fails for monsters in Peaceful; fixed spawn chunks removed, but forceloaded chunks, portal-active chunks, and the area around the player are still preloaded. — [Minecraft Wiki, Java Edition 25w31a](https://minecraft.wiki/w/Java_Edition_25w31a)
- 25w44a: `/worldborder` time arguments accept `s` and `d` suffixes; loot tables gained `minecraft:slots` entry and slot sources; game-test `bool_rule`/`int_rule` replaced by `rules` map. — [Minecraft Wiki, Java Edition 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a)
- 26.1: new `/swing <entity> <mainhand|offhand>`; new `/fetchprofile entity <selector>`; `/time` rebased on world clocks — optional `of <clock>`, `set`/`add` now return the clock's total elapsed ticks, new `pause`, `resume`, `query <timeline>`, `rate <rate>` (0 < rate ≤ 1000), `query gametime` unchanged, Overworld markers `day`, `noon`, `night`, `midnight`; data-driven villager trades (`villager_trade/`, `trade_set/`); new number providers `environment_attribute`, `sum`; new predicate `environment_attribute_check`; banner/sign default `rotation` 0 → 8; Structure Block output moves from `structures` to `structure`. — [Minecraft Wiki, Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- 26.2: new `/unpublish`; `/team modify <name> color` and `/waypoint modify <name> color` accept only lowercase snake_case colour names (`dark_purple`, not `darkpurple`/`DarkPurple`), matching text-component colour names; advancement grant/revoke output now counts advancements and players; `/execute on owner` treats vexes as owned by their evoker; entity predicates redesigned — `type` → `minecraft:entity_type`, type-specific sub-predicates moved to `minecraft:type_specific/*` (`slime` → `type_specific/cube_mob`), unrecognised sub-predicate keys now rejected, new `minecraft:entity_tags`; `HurtByTimestamp` removed (use `ticks_since_last_hurt_by_mob`); `minecraft:bed` block entity removed; tag `#concrete_powder` → `#concrete_powders`; worldgen feature `pointed_dripstone` → `speleothem`. — [Minecraft Wiki, Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)

## Key Question 6: World save format — level.dat split and `data/<namespace>/*.dat`

### Takeaway
26.1 Snapshot 6 (data pack format 99, early 2026) split `level.dat`: game rules, scheduled events, weather, wandering trader, worldgen settings, world clocks, boss events and the dragon fight moved to namespaced files under `data/minecraft/` (e.g. `game_rules.dat`, `scheduled_events.dat`, `scoreboard.dat`), dimensions moved under `dimensions/<ns>/<dim>/`, player data under `players/`, and command storage into per-namespace subfolders; `Player` was replaced by `singleplayer_uuid`. Any tool that reads `level.dat` directly (Amulet, NBT libraries) must be updated to the new layout for 26.1+ worlds.

### Cited Findings
- "`level.dat` was split in 26.1 Snapshot 6": moved out of `level.dat` into the `data` folder — "game rules, scheduled events, weather, Wandering Trader, world generation settings, world clocks, boss events, and the Ender Dragon fight. The top-level `data` folder now holds only data shared across dimensions, and data in it is namespaced." — [Minecraft Wiki, Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format)
- Current `data/minecraft/` contents: `game_rules.dat`, `scoreboard.dat`, `scheduled_events.dat`, `wandering_trader.dat`, `weather.dat`, `world_clocks.dat`, `world_gen_settings.dat`, `custom_boss_events.dat`, `random_sequences.dat`, `stopwatches.dat`. Overworld files under `dimensions/minecraft/overworld/`; dragon fight at `dimensions/minecraft/the_end/data/minecraft/ender_dragon_fight.dat`. Command storage "moved to namespace subfolders instead of having a namespace suffix." — [Minecraft Wiki, Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format)
- Remaining `level.dat` `Data` keys: `allowCommands`, `DataPacks`, `DataVersion`, `difficulty_settings`, `enabled_features`, `GameType`, `initialized`, `LastPlayed`, `LevelName`, `singleplayer_uuid`, `ServerBrands`, `spawn`, `Time`, `version`, `Version`, `version_history`, `WasModded`. "Game rules are stored in `data/minecraft/game_rules.dat`, not in `level.dat`." — [Minecraft Wiki, Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format)
- 26.3 Snapshot 7: "Added a `version_history` list to `level.dat`." — [Minecraft Wiki, Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format)
- 26.1 release notes (save format): `Player` → `singleplayer_uuid`; difficulty into `difficulty_settings` with `difficulty` as a string (`peaceful|easy|normal|hard`) and `DifficultyLocked` → `locked`; renamed fields on move (`DragonKilled` → `dragon_killed`, `rainTime` → `rain_time`); Overworld, `DIM-1`, `DIM1` move into `dimensions/`; `advancements`, `playerdata`, `stats` move under `players/`; `resources.zip` → `resourcepacks/`; `scoreboard.dat` → `data/minecraft/scoreboard.dat`; `chunks.dat` → `chunk_tickets.dat`; map files renamed to just the number and `idcounts.dat` → `last_id.dat`; `raids_end.dat` removed (End uses `raids.dat`); Structure Block output `structures` → `structure`. — [Minecraft Wiki, Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- 26.1 Snapshot 6 data pack format is 99 (26.1 S5 = 98, S7 = 99.1). — [Minecraft Wiki, Pack format](https://minecraft.wiki/w/Pack_format)
- 26.2: "Certain worlds from before 26.1 can now upgrade faster"; MC-307418 fixed a crash upgrading a legacy world. — [Minecraft Wiki, Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- 26.1 runtime: default RAM allocation 2 GB → 4 GB; GC G1GC → ZGC on compatible machines; bundled JDK Microsoft OpenJDK 25. — [Minecraft Wiki, Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)

### Inferences
- The data-version boundary for the split is between 1.21.11 (format 94.1) and 26.1 (data version 4786). A tool can detect the new layout by `DataVersion >= 4786` or simply by the presence of `dimensions/` and `data/minecraft/game_rules.dat`.
- Command storage path: previously `data/command_storage_<namespace>.dat`; now `data/<namespace>/command_storage.dat` (the wiki says "namespace subfolders instead of having a namespace suffix" but does not print the filename; the exact filename needs verification).
- Because `scoreboard.dat`, `game_rules.dat` and `scheduled_events.dat` are now separate NBT files, a Python NBT library can edit game rules or scheduled functions without touching `level.dat`, but the internal NBT schema of `game_rules.dat` (keyed by namespaced ID, typed bool/int values per the MSMP 2.0.0 note in 25w44a) is not documented in the fetched sources.
- Region/chunk file layout under `dimensions/minecraft/overworld/region/` is a pure relocation; Amulet-style tools need only path changes plus the new `level.dat` keys, unless the chunk format itself changed (not seen in fetched changelogs).

### Gaps
- Exact per-file NBT schemas for `game_rules.dat`, `scheduled_events.dat`, `scoreboard.dat` and the per-namespace command storage filename were not found.
- The wiki fetch did not state when `random_sequences.dat` and `stopwatches.dat` appeared.
- No source on Amulet or NBT-library (e.g. nbtlib, pymclevel) support status for 26.x layouts; this must be checked against each tool's changelog.

## Key Question 7: Launcher/log location on macOS and log rotation

### Takeaway
The vanilla launcher's game directory on macOS is `~/Library/Application Support/minecraft`, with logs in `logs/latest.log` and archives named `yyyy-mm-dd-N.log.gz`. The client uses a Log4j 2 `RollingRandomAccessFile` appender with `OnStartupTriggeringPolicy`, which archives the previous `latest.log` on each launch; a known Mojang bug (MC-248288) shows a second concurrently-launched instance rotating the file out from under the first, and buffered appenders can delay writes to disk.

### Cited Findings
- Vanilla launcher game folder on macOS: `~/Library/Application Support/minecraft` (via Finder "Go to Folder"); logs are in the `logs` folder inside it; custom game directories put `logs/` and `crash-reports/` under that directory instead (open via the folder icon on the Installations tab). — [Nodecraft, finding client logs](https://nodecraft.com/support/games/minecraft/mods/how-to-find-client-logs-on-modded-minecraft-launchers)
- "the latest log is called latest.log. Previous logs have the pattern yyyy-mm-dd_number.log.gz"; file extensions are hidden by default so it may appear as "latest". — [Fabric Wiki, logs tutorial](https://wiki.fabricmc.net/_export/raw/player:tutorials:logs)
- Forge's client `log4j2.xml` (mirrors vanilla's approach): the file appender "is a RollingRandomAccessFile that writes to logs/latest.log, and its policies include TimeBasedTriggeringPolicy and OnStartupTriggeringPolicy (the rollover strategy keeps up to 99 files)." — [MinecraftForge log4j2.xml](https://github.com/MinecraftForge/MinecraftForge/blob/2f5172f907a74a04dbac9cd28b9507079951bf2b/src/fmllauncher/resources/log4j2.xml); same pattern on [wiki.vg Debugging](https://wiki.vg/Debugging)
- Log4j 2 semantics: `OnStartupTriggeringPolicy` "causes a rollover only once during the lifetime of a JVM" — if the log file was created before the JVM's start time and meets `minSize` (default 1 byte); `RollingRandomAccessFile` "always enables the internal buffer" (default `bufferSize` 8192, `immediateFlush` default true but configurable). — [Apache Log4j 2 Rolling File Appenders](https://logging.apache.org/log4j/2.x/manual/appenders/rolling-file.html)
- Mojang bug MC-248288 (filed against 22w03a, unresolved as of the fetched copy): when two Java Edition instances run at once, "the second one rotates `latest.log` while the first keeps writing, which can wipe out the first instance's messages." — [Mojira MC-248288](https://bugs.mojang.com/browse/MC-248288)
- Custom log config: the launcher's "Log config" option or `-Dlog4j.configurationFile=`; "if the file specified cannot be found, the default one will silently be used instead." — [wiki.vg Debugging](https://wiki.vg/Debugging)

### Inferences
- "latest.log looks stale while the game is running" has three plausible causes supported by the above: (1) the running instance writes to a different game directory (custom installation dir), (2) a second instance (or a quick relaunch) rotated the file via `OnStartupTriggeringPolicy` so the first instance's handle now points at a renamed/gz'd file, (3) the appender buffer — if the vanilla config sets `immediateFlush="false"`, lines sit in the 8 KB buffer until it fills. A watcher should tail by inode / re-open on rotation and also scan the newest `*.log.gz`.

### Gaps
- The vanilla client's actual Log4j config (`client-1.12.xml`, referenced from the version JSON `logging` block) was not fetched, so its `immediateFlush` setting is unconfirmed; only Forge's near-identical config and the Log4j defaults are cited.
- No source documents the 26.x client log path changing; it is assumed unchanged from the long-standing `logs/latest.log`.
