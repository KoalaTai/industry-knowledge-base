# Templates plus RCON retire the keystroke pipeline

Yes, there is a clearly better way, and it is two changes rather than one. First, replace the per-block `fill`/`setblock` emitter in the Python generator with a tiler that writes vanilla **structure templates (`.nbt`, max 48×48×48 each)** into the same datapack and places them with one `/place template … strict` command per tile; that collapses **~151,000 commands into a few hundred to a few thousand**, keeps the zero-mod, drop-in datapack story, and reuses the existing `schedule`/`forceload` sequencer ([Minecraft Wiki: Structure file](https://minecraft.wiki/w/Structure_file); [Commands/place](https://minecraft.wiki/w/Commands/place)). Second, replace AppleScript keystrokes with **RCON to a local Paper or vanilla 26.3 dedicated server** that hosts a copy of Animus, wrapped in a ~50-line MCP bridge so Claude Code can send commands and read text responses; RCON does not exist on the singleplayer client and no 26.x mod adds it, so the server hop is the price of a real control channel ([Minecraft Wiki: RCON](https://minecraft.wiki/w/RCON)). The immediate blocker is a one-line fix: snapshot 25w44a moved every game rule into a registry with namespaced snake_case IDs, so `maxCommandChainLength` is now `max_command_sequence_length`, and because any unparseable line stops the whole `.mcfunction` from loading, the load function died silently ([Minecraft Wiki: 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a); [Function](https://minecraft.wiki/w/Function_(Java_Edition))). The alternatives are weaker for this job: every Mineflayer-based bot and MCP server is stuck at protocol 775 (26.1) with 26.2/26.3 pull requests still open; WorldEdit 7.4.6 and Litematica 0.29.1 do run on 26.3 as Fabric client mods and are good interactive fallbacks; Amulet is the only offline editor tracking the 26.1 save-format overhaul. No official Anthropic Minecraft demo exists; the viral Fable 5.1 / Mythos / Opus 5.5 "Minecraft" clips are browser voxel clones, and the real in-game Claude builders are community projects wired through Mineflayer bots, Paper plugins with WebSocket bridges, or RCON scripts driven from Claude Code.

## The 26.x line broke your commands, not your approach

Mojang's switch to year-based versioning hides how much has moved under a datapack author in eighteen months. 1.21.11 was the last 1.x release; **26.1 shipped 24 March 2026 (data version 4786, pack format 101.1, Java 25 required)**, 26.2 on 16 June, and **26.3 "Wilderness Bound" on 15 September 2026 (data version 5023, pack format 121.0)**, with 26.4 Snapshot 6 already at format 125.1 ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3); [Pack format](https://minecraft.wiki/w/Pack_format)). Roughly quarterly drops mean "tested on 1.21.x" now means "predates the entire line you are running".

The rename that hit the load function is the 25w44a registry change: "All game rules have now been moved into a registry," with camelCase names replaced by `minecraft:`-namespaced snake_case IDs. The explicit table maps `maxCommandChainLength → max_command_sequence_length`, `maxCommandForkCount → max_command_forks`, `commandModificationBlockLimit → max_block_modifications`, `doDaylightCycle → advance_time`, `doMobSpawning → spawn_mobs`, `doWeatherCycle → advance_weather`, and inverts three booleans (`disableRaids → raids`, `disableElytraMovementCheck → elytra_movement_check`, `disablePlayerMovementCheck → player_movement_check`); `doFireTick` was replaced outright by the integer rule `fire_spread_radius_around_player` ([Minecraft Wiki: 25w44a](https://minecraft.wiki/w/Java_Edition_25w44a)). No source documents old names being accepted as aliases, and the existence of a "Classic Gamerule" mod whose author says the change "broke all existing usage of gamerules" is strong evidence they are rejected ([CurseForge: Classic Gamerule](https://www.curseforge.com/minecraft/mc-mods/classic-gamerule)). The default for `max_command_sequence_length` is still **65,536 commands per function call, nested calls included**, and commands beyond it are ignored rather than erroring ([Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition))).

The reason the failure was invisible is a design decision, not a bug: "if any of the lines in a function file is unparseable, the function file cannot be loaded," and the only report is a log line of the form `Failed to load function … Whilst parsing command on line N` in the server (or, in singleplayer, the client) log; Mojira MC-121768 has tracked the lack of a chat-side message for years and a commenter notes that a function that errors "isn't added to the loaded list, which is by design" ([Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition)); [Mojira MC-121768](https://mojira.dev/MC-121768); [example Paper log](https://api.mclo.gs/1/raw/rydMWKQ)). Any generator that emits 1,288 files must therefore grep `latest.log` for `Failed to load function` after every `/reload`; chat will only ever say "Reloading!".

Three further 26.x-era changes matter for the AC Worlds generator. The `pack.mcmeta` schema changed in 25w31a: `min_format` and `max_format` are now required, `supported_formats` is removed unless the pack also claims formats below 82, and a plain integer `max_format` means "any minor version" ([Minecraft Wiki: 25w31a](https://minecraft.wiki/w/Java_Edition_25w31a)). For a pack that only needs to run on 26.3, emit `"min_format": 121, "max_format": 125` (or a plain `121`) and drop the legacy fields. All datapack folders went singular in 1.21 (`function/`, `structure/`, `tags/function/`), which the user has evidently already absorbed since the pack loads at all ([Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)). And 1.21.5 added the `strict` keyword to `/fill`, `/setblock`, `/clone` and `/place template`, which places blocks "as-is without triggering block updates and shape updates"; `/fill` itself is bounded by the `max_block_modifications` rule (historically 32,768 blocks) and fails if either corner is in an unloaded chunk ([Minecraft Wiki: Commands/fill](https://minecraft.wiki/w/Commands/fill); [Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)). Nothing in the 26.1–26.4 changelogs renames the ordinary building blocks (stone, concrete, glass, wool) that a landmark generator emits; the 26.x renames are in worldgen features, tags and predicates ([Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2); [Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)). The practical conclusion is that the datapack approach is sound; the current emitter is simply verbose, and the sequencer needs `strict` on every placement plus the renamed game rules.

## Structure templates cut 151,000 commands to a few thousand

The cheapest large win is a format change inside the datapack. Vanilla structure templates are gzipped NBT files with a `palette` of block states and a sparse `blocks` list of `{state, pos}` entries, stored at `data/<namespace>/structure/<name>.nbt` and loadable both by structure blocks and by `/place template` ([Minecraft Wiki: Structure file](https://minecraft.wiki/w/Structure_file)). The `/place template <id> [<pos>] [<rotation>] [<mirror>] [<integrity>] [<seed>] [strict]` command has no documented size limit of its own, supports rotation and mirroring, and since 1.21.5 accepts `strict` to suppress update cascades; it fails only if the template ID is missing, the template is empty, or any chunk it would touch is unloaded ([Minecraft Wiki: Commands/place](https://minecraft.wiki/w/Commands/place)). Templates are written trivially from Python with `nbtlib` 2.0.4, which handles gzipped NBT with schema-enforced tag types ([PyPI: nbtlib](https://pypi.org/pypi/nbtlib/json)).

The constraint is the **48×48×48 per-axis cap**, unchanged since 1.16 and still in force on 26.3 ([Minecraft Wiki: Structure Block](https://minecraft.wiki/w/Structure_Block)). The cap is enforced by the structure-block UI rather than the file format; the Spigot `Structure` API notes it can create templates "larger than the 48x48x48 size that Minecraft's Structure blocks support," and community tools such as `structure-tools` glue oversized files with a `writeFakeSize` hack ([Spigot Javadocs: Structure](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/structure/Structure.html); [Marcono1234/structure-tools](https://github.com/Marcono1234/structure-tools)). No source confirms that `/place template` on 26.3 will honour a datapack template larger than 48 per axis, so the safe design is to tile every landmark into ≤48³ cubes (32³ if you want headroom) and emit one `/place template acworlds:<model>/<tile> x y z none none 1.0 0 strict` per tile. For 119 models currently costing ~151,000 commands, that is a few hundred to a few thousand lines, two orders of magnitude fewer, and each line is short enough to fit any transport, including RCON's 1446-byte payload limit discussed below. Because `blocks` is a sparse list, air can simply be omitted, which makes files small but also means an omitted position leaves existing terrain untouched; if a landmark needs its site cleared, keep one `fill … air strict` per footprint ahead of the tile placements.

Everything else about the current pipeline survives. The sequencer still needs `forceload add` before placing, since `/place template` fails on unloaded chunks; each `forceload add` is capped at **256 chunks** and chunk loading has been asynchronous since 1.17, so schedule the placement at least one tick after the forceload ([Minecraft Wiki: Commands/forceload](https://minecraft.wiki/w/Commands/forceload)). Write `DataVersion: 5023` into each template so no DataFixer upgrade is needed. Raising `max_block_modifications` lets any remaining `fill` slabs be larger, and community guidance that "a few commands per tick are negligible" while `/fill` and `/clone` are "especially laggy" argues for spreading tile placements over ticks exactly as the existing `schedule` chain already does ([Planet Minecraft forum](https://www.planetminecraft.com/forums/minecraft/datapacks/constantly-run-a-function-from-within-the-data-pack-669700/)).

The mod-based import formats are all alive on 26.3 and are the right fallback when a model must be placed as one unit with rotation, masking and undo. **WorldEdit 7.4.6 (15 October 2026)** ships a Fabric/NeoForge build for 26.3 that runs client-side in singleplayer; `.schem` files go in `config/worldedit/schematics/`, loaded with `//schem load` and placed with `//paste -a` to skip air, with no documented clipboard size limit ([Modrinth API: WorldEdit](https://api.modrinth.com/v2/project/worldedit/version); [WorldEdit docs: Clipboard](https://worldedit.enginehub.org/en/latest/usage/clipboard/)). FAWE 2.16.x supports 26.3 but only as a Paper/Spigot plugin, with no Fabric build, so it is relevant only if the local server route below is adopted and pastes grow into the tens of millions of blocks ([Modrinth API: FAWE](https://api.modrinth.com/v2/project/fastasyncworldedit/version)). For writing `.schem` from Python, `mcschematic` 11.4.4 was released 7 February 2026, before 26.1 existed, so its `Version` enum cannot contain 26.x data versions; the cleaner route is to write Sponge v2/v3 NBT directly with `nbtlib` and `DataVersion: 5023` ([PyPI: mcschematic](https://pypi.org/pypi/mcschematic/json); [SpongePowered/Schematic-Specification](https://github.com/SpongePowered/Schematic-Specification)). **Litematica 0.29.1 + MaLiLib 0.30.2 (27 September 2026)** target 26.3 and offer a Creative "Paste Schematic in world" that writes the whole schematic directly in singleplayer, with `litemapy` 0.11.0b0 (June 2025 beta) as the Python writer; it is the best previewing tool but the weakest for a scripted 119-model batch because every placement is a GUI action ([litematica.com](https://litematica.com/latest-version/); [PyPI: litemapy](https://pypi.org/project/litemapy/)). **Axiom 6.1.5 (28 October 2026)** has a 26.3 Fabric build and is free for non-commercial singleplayer under an all-rights-reserved licence, but its documentation on bulk schematic import could not be retrieved, and it is designed for hand-building rather than scripted import ([Modrinth API: Axiom](https://api.modrinth.com/v2/project/axiom/version); [Modrinth: Axiom](https://modrinth.com/mod/axiom)).

Offline editing is the highest-ceiling and highest-risk option. 26.1 rewrote the save layout: region files moved to `dimensions/minecraft/overworld/region/`, player data to `players/data/`, game rules and scoreboard to namespaced `data/minecraft/*.dat`, `level.dat`'s `Player` became `singleplayer_uuid`, and a `region-file-compression` setting (including LZ4) arrived; Paper's notes call backups "absolutely mandatory" and warn "you cannot downgrade" ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format); [PaperMC news: 26.1](https://papermc.io/news/26-1)). That kills every unmaintained Anvil library: `anvil-parser` was archived in May 2023 and will not even find the region folder ([GitHub: anvil-parser](https://github.com/matcool/anvil-parser)). **Amulet** is the only offline editor with explicit 26.x work ("Implement Java 26.1" in 0.10.54b1, "Java 26.3 block format fix" in 0.10.64 on 28 September 2026), and `amulet-core` 1.9.51 (30 October 2026, Python ≥3.11) is the free library behind the paid GUI ([Amulet-Map-Editor releases](https://github.com/Amulet-Team/Amulet-Map-Editor/releases); [PyPI: amulet-core](https://pypi.org/project/amulet-core/)). It has no tick budget, no chunk-loading step and no 48-block cap, but the evidence of 26.3 support is commit titles rather than a support table, the game must be closed during the write, and it should only ever touch a duplicate of `saves/Animus`.

## RCON beats AppleScript, but only on a dedicated server

The AppleScript keystroke channel has three defects that no amount of tuning removes: it is blind (no return value), it is slow (one chat line at a time through the GUI), and it depends on window focus. RCON fixes all three, with caveats. It is a Java Edition dedicated-server feature enabled in `server.properties` (`enable-rcon=true`, `rcon.password`, `rcon.port=25575`), its wire protocol is the frozen Source RCON format, and **command output is returned in the response payload**, although "many commands return nothing" and unknown commands cannot be reliably detected ([Minecraft Wiki: RCON](https://minecraft.wiki/w/RCON)). Outbound payloads are capped at roughly **1446 bytes**, inbound responses are fragmented into 4096-byte packets with no reliable terminator, and the standard workaround is to send a junk packet and read until the server echoes "Unknown request" for it ([Minecraft Wiki: RCON](https://minecraft.wiki/w/RCON); [mctools RCON docs](https://mctools.readthedocs.io/en/master/rcon.html)). Two Claude-driven build projects hit these limits in practice: `aoe2mc` had to keep every generated command under 1446 bytes because oversize commands stopped the game, and `clawdcraft` found that "failed commands often return empty strings over RCON" and switched to verifying with `execute if entity …` probes ([Larspolo/aoe2mc PR #1662](https://github.com/Larspolo/aoe2mc/pull/1662); [adrianwedd/clawdcraft](https://github.com/adrianwedd/clawdcraft)). Structure templates sidestep the 1446-byte limit entirely because each placement is one short command, and a `/function acworlds:build_all` call over RCON triggers thousands of lines from disk with a single packet.

The catch is that **RCON is unavailable in singleplayer**. The LAN-world tutorial never mentions RCON or `server.properties`, searches found no 26.x mod that adds RCON to the integrated server, and the closest client-side analogue, LCon (a WebSocket command server on port 8115), is Forge-only for 1.19.2/1.20.1 and two years stale ([Minecraft Wiki: Setting up a LAN world](https://minecraft.wiki/w/Tutorial:Setting_up_a_LAN_world); [Modrinth: LCon](https://modrinth.com/mod/lcon-local-console-access)). The realistic workflow is a local dedicated server: `brew install openjdk@25`, a Paper or vanilla 26.3 jar, a copy of `saves/Animus` as the server's world folder, and the normal client connecting to `localhost` so the user watches Claude build live in the same world ([PaperMC: Java install](https://docs.papermc.io/misc/java-install/); [PaperMC: getting started](https://docs.papermc.io/paper/getting-started/)). The world folder cannot be open in the client and the server simultaneously, so Animus either moves to the server permanently (still effectively singleplayer, now with RCON) or gets copied back after each build session. A working precedent for exactly this on 26.3 is `mciwb`, a Python RCON world builder whose quick start runs a Minecraft 26.3 server in podman and ships a `.claude/skills/minecraft-build` skill walking an agent through survey, build, inspect and iterate ([gilesknap/mciwb](https://github.com/gilesknap/mciwb); [mciwb PR #162](https://github.com/gilesknap/mciwb/pull/162)).

On the Python side, the RCON protocol being frozen means the 2021-era `mcrcon` 0.7.0 still works, but `rconx` 0.3.0 (21 October 2026) and `mctools` 1.4.1, which enforces the outbound limit and handles fragmentation, are the safer picks for new code ([PyPI: rconx](https://pypi.org/project/rconx/); [mctools RCON docs](https://mctools.readthedocs.io/en/master/rcon.html); [libraries.io: mcrcon](https://libraries.io/pypi/mcrcon)). For Claude Code, RCON-backed MCP servers are near-interchangeable thin wrappers: `Faneraiy14/minecraft-rcon-mcp` is a zero-dependency Node implementation added with one `claude mcp add` line using host/port/password environment variables, with a note that several MCP servers starting at once can hit Claude Code's 30-second startup timeout ([Faneraiy14/minecraft-rcon-mcp](https://github.com/Faneraiy14/minecraft-rcon-mcp)). A custom FastMCP bridge of about fifty lines over `rconx` is equally viable and avoids trusting a stranger's password handling; the design rules that fall out of the sources are to bind to 127.0.0.1 only, never put the password in argv, keep every command under 1446 bytes, pair each mutating command with an `execute if block`/`data get block` probe, and read responses with the junk-packet terminator.

If staying strictly inside the singleplayer client is non-negotiable, two routes remain, both unproven. `MairwunNx/minecraft-mcp` exposes 51 tools (blocks, entities, commands, logs, undo for agent builds) over a companion WorldAPI mod that reportedly "runs on Paper, Fabric, or NeoForge servers, and in singleplayer with the WorldAPI mod installed," but the WorldAPI repository returned 404 and its Modrinth slug was not found, so its 26.3 status is unverified ([MairwunNx/minecraft-mcp](https://github.com/MairwunNx/minecraft-mcp)). Alternatively, a tiny custom Fabric client mod can open a localhost WebSocket and call the client's command-send method, which FabricMC confirms is the same path chat uses; Fabric is stable on 26.3, but this is bespoke code and feedback only reaches the socket if the mod also hooks chat messages as LCon does ([FabricMC discussion #1489](https://github.com/orgs/FabricMC/discussions/1489)). Either way, the singleplayer read-back problem the user already noticed (a stale `latest.log`) has a sanctioned fix: the launcher's `client.json` passes `-Dlog4j.configurationFile=${path}`, so a custom Log4j2 XML can add a non-rolling appender for chat and command feedback alongside the vanilla `RollingRandomAccessFile`, whose `OnStartupTriggeringPolicy` rotates `latest.log` on launch and whose internal buffer can delay writes; Mojira MC-248288 documents a second instance rotating the file out from under the first ([Minecraft Wiki: client.json](https://minecraft.wiki/w/Client.json); [Log4j rolling file appenders](https://logging.apache.org/log4j/2.x/manual/appenders/rolling-file.html); [Mojira MC-248288](https://bugs.mojang.com/browse/MC-248288)).

## Mineflayer bots are stranded at 26.1, which sorts the MCP field

Minecraft MCP servers split into three families, and the version wall sorts them cleanly. The Mineflayer family, in which a Node "fake player" joins the game and exposes move, look, place-block, dig-block, inventory and chat tools, is the most demo-friendly and the most version-fragile. Mineflayer's documented support runs 1.8 through **26.1** (v4.39.0); as of 17–18 October 2026, minecraft-protocol 1.68.0 and minecraft-data 3.117.0 have no data for protocols 776 and 777, the 26.3 pull request (mineflayer #4146, opened 21 September) is still open, and a maintainer-side comment states "mineflayer does not support 26.3, neither does it support 26.2" ([Mineflayer site](http://prismarinejs.github.io/mineflayer/); [mineflayer PR #4146](https://github.com/PrismarineJS/mineflayer/pull/4146); [VitaminMCP issue #4](https://github.com/Backas03/VitaminMCP/issues/4)). The reference `yuniko-software/minecraft-mcp-server` is frozen at 1.21.11; the best-maintained fork, `CDX-1/minecraft-client-mcp`, supports 26.1.x, adds a top-down PNG capture and a one-line Claude Code install, and explicitly says 26.2 is unsupported because "the current Mineflayer stack lacks complete 26.2 game data" ([yuniko-software/minecraft-mcp-server](https://github.com/yuniko-software/minecraft-mcp-server); [CDX-1/minecraft-client-mcp](https://github.com/CDX-1/minecraft-client-mcp)). The documented workaround, ViaVersion + ViaBackwards on a 26.3 server so a protocol-775 bot can join, works but leaves the bot with a lossy view of 26.2/26.3 content ([VitaminMCP issue #4](https://github.com/Backas03/VitaminMCP/issues/4)). Even when they work, these bots place one block per tool call as a player would, which is the wrong primitive for 119 landmarks.

The RCON family (Faneraiy14, MinecraftCodeFoundary, Peterson047's Python FastMCP server, and generic Source-RCON servers) is version-agnostic because only the command text inside the packet evolves, and it is the family that actually talks to a 26.3 game today ([Faneraiy14/minecraft-rcon-mcp](https://github.com/Faneraiy14/minecraft-rcon-mcp); [MinecraftCodeFoundary/Minecraft-MCP-Server](https://github.com/MinecraftCodeFoundary/Minecraft-MCP-Server)). The plugin-backed family, where a server-side mod exposes a REST/WebSocket world API, is the richest when it works: MairwunNx's 51 tools with undo and logs, and `VitaminMCP` 3.2.1 whose agent side "supports Minecraft 26.2 and 26.3, checked by hand on Paper 26.2-134 and 26.3-200" for events, logs, state queries and commands, while its bundled Mineflayer bots still cannot join ([MairwunNx/minecraft-mcp](https://github.com/MairwunNx/minecraft-mcp); [VitaminMCP issue #4](https://github.com/Backas03/VitaminMCP/issues/4)). A fourth, offline category is also worth knowing: `simonerecchia/minecraft-schematic-lab` and `joshdevous/minecraft-builder-claude-mcp-server` let Claude design, preview and export WorldEdit `.schem` files without a live game, which is structurally the same idea as the template tiler proposed here ([minecraft-schematic-lab](https://github.com/simonerecchia/minecraft-schematic-lab); [joshdevous/minecraft-builder-claude-mcp-server](https://github.com/joshdevous/minecraft-builder-claude-mcp-server)). Nothing official from Anthropic exists in any family.

The embodied-agent frameworks are the wrong tool for bulk construction regardless of version. **Baritone** has official releases for 26.1 (v1.18.0) and 26.2 (v1.19.0) but is a client-side pathing mod with no external endpoint, usable by Claude only indirectly through chat-typed `#goto` commands ([cabaletta/baritone releases](https://github.com/cabaletta/baritone/releases)). **Mindcraft** (~6.0k stars) supports Anthropic as one of roughly seventeen providers via `ANTHROPIC_API_KEY`, but it is Mineflayer-bound ("up to v1.21.11, recommend v1.21.6"), ships with LLM code execution disabled by default and warns the sandbox is still injection-vulnerable ([mindcraft-bots/mindcraft](https://github.com/mindcraft-bots/mindcraft)). **Voyager** is GPT-4-only officially and last updated in 2024; the community fork that tried other models reported Claude 3.5 Sonnet as the best Claude but found everything other than GPT-4 did "not well" ([MineDojo on GitHub](https://github.com/MineDojo); [JVP15/Voyager-LLM-Trials](https://github.com/JVP15/Voyager-LLM-Trials)). All of these are built for survival-style play where a bot walks and clicks; a single `/place template` or `/fill` moves thousands of blocks in one command, and that is the regime a landmark import lives in.

## The viral Claude Minecraft demos are mostly browser clones

The 2026 "Claude built Minecraft" material splits into two categories that headlines blur. The dominant one is **Minecraft clones**: the model writes a voxel game from scratch, usually one HTML/three.js file, and never touches real Minecraft. Min Choi's "Fable 5.1 one-shotted Minecraft from a single prompt," the June 2026 Mythos clone with "voxel terrain, chunk generation progress bar, working hotbar," the Fable 5 launch-week clones (one at ~3K lines of code for ~$12 of API), TweakTown's "built Minecraft for less than $50" Reddit story, and Opus 5.5's "Lumen Vale" browser game after 1 hour 37 minutes at max effort are all this category ([x.com/minchoi](https://x.com/minchoi/status/2094990530513903710); [awesome-claude-fable-5](https://github.com/Anil-matcha/awesome-claude-fable-5); [TweakTown](https://www.tweaktown.com/news/112130/anthropics-latest-ai-model-claude-fable-just-built-minecraft-for-less-than-dollars50/index.html); [x.com/dreyk0o0](https://x.com/dreyk0o0/status/2103822946800165270)). The Aug–Oct 2026 YouTube cluster ("Claude Fable 5 Makes Minecraft in 1 Minute vs 10 Minutes vs 1 Hour," "Claude Opus 5 Makes Minecraft In 1 Min vs 1 Hour vs 1 Day," "Claude Sonnet 5.5 Vs ChatGPT 6.1 Sol Make a Minecraft Mod From Scratch," "I Asked Claude AI to Make a Fully Custom Minecraft Server") is the same: coding videos of clones, Fabric mods or server plugins, with channel names and tooling unverifiable because YouTube watch pages return no metadata to a fetcher ([YouTube: Fable 5 1/10/60 min](https://www.youtube.com/watch?v=qfOqmYDFv8c); [YouTube: Opus 5 1 min/1 hr/1 day](https://www.youtube.com/watch?v=7wubbIdBI1Y); [YouTube: Sonnet 5.5 vs ChatGPT 6.1](https://www.youtube.com/watch?v=68v3BKaLUW0)). **No official Anthropic demo, blog post or livestream of Claude Fable 5.1 or any Claude 5 / Mythos model building inside real Minecraft was found**; Wikipedia's Claude Mythos article, which dates Fable 5 (9 June 2026) and Fable 5.1 (1 September 2026), never mentions Minecraft, and the one page claiming an "Anthropic experiment" cites no Anthropic source and blends in the 2024 Claude 3.5 Sonnet Mindcraft runs ([Wikipedia: Claude Mythos](https://en.wikipedia.org/wiki/Claude_Mythos); [Brandeploy](https://www.brandeploy.io/en-claude-the-architect-and-minecraft)).

The one Fable 5.1 item that touched real Minecraft is instructive for how it was wired: the r/ClaudeAI "Fable 5.1 made a Minecraft mod for $20" post used the third-party `atomic.chat` agent harness with an Anthropic key, analysed two YouTube reference clips frame by frame, used Blender MCP to model a dragon and gun, and produced a Fabric 1.21.1 mod for $20.54 and ~383.6K output tokens in about an hour, with one fix round for a dragon that flew upside down ([explainx.ai](https://explainx.ai/blog/fable-5-1-minecraft-mod-kirin-dragon-blender-mcp-2026)). It is a mod-development demo, not an in-game build, and it did not use Claude Code or any game bridge.

The real in-game Claude builders are community projects, and their wiring is the useful evidence. yuniko's Eiffel Tower and White House builds used a Mineflayer bot joining a singleplayer world opened to LAN on port 25565, driven from Claude Desktop, with documented failure modes of version lock-in (1.21.11), needing a full Desktop restart, and the MCP not triggering unless the prompt names Minecraft ([yuniko-software/minecraft-mcp-server](https://github.com/yuniko-software/minecraft-mcp-server)). `IotA-asce/minecraft-mcp` runs Claude Code over stdio to a Node server, to a WebSocket on 127.0.0.1:8765, to a Java Paper plugin; block placement and `run_command` work with no player online, and the showcase is Claude writing TypeScript build scripts (`build-castle.ts`, a lighthouse, an "Aurelian Reach" megastructure) that the harness executes, configurable for 26.2 ([IotA-asce/minecraft-mcp](https://github.com/IotA-asce/minecraft-mcp)). `clawdcraft` keeps Claude Code in a tmux session, tails the Paper server's `logs/latest.log` for chat, and acts through a small set of pre-approved RCON scripts ([adrianwedd/clawdcraft](https://github.com/adrianwedd/clawdcraft)). The Show HN ClaudeCraft used Mineflayer plus the Claude Agent SDK with Opus 4.6 on 1.21.11, taking `@Name build me a house` from chat ([Hacker News](https://news.ycombinator.com/item?id=47029874)). AgentCraft (October 2026) is a Fabric mod that turns Minecraft into a "walkable studio" for Claude coding agents with git worktrees and in-game diffs, but the agents represent coding work rather than building structures ([hermes-ai.net](https://hermes-ai.net/news/agentcraft-turns-minecraft-into-a-live-claude-coding-agent-control-room/)). The two computer-use experiments, including one running Opus 4.6 on Java 26.1.1 on macOS 15 via a `.app` wrapper so the bare `java` process clears the allowlist, both conclude that screenshot-and-keystroke control is latency-bound and imprecise and fall back to typed chat commands "because they tolerate latency," which is the same dead end as the AppleScript pipeline ([SauersML/claude-plays-minecraft](https://github.com/SauersML/claude-plays-minecraft); [ObservedObserver/claude-minecraft-use](https://github.com/ObservedObserver/claude-minecraft-use)).

MC-Bench shows where the model community thinks build quality lives. It is a pairwise human-vote Elo benchmark in which models write code executed by a "builder" container against containerised Minecraft servers, the result rendered in a Prismarine-style web viewer; its last verifiable snapshot (March 2025) had Claude 3.7 Sonnet first and Claude 3.5 Sonnet second over 10,000+ samples, but the GitHub org shows little activity after September 2025 and the live late-2026 leaderboard could not be retrieved ([TechCrunch](https://techcrunch.com/?p=2982775); [github.com/mc-bench](https://github.com/mc-bench); [favtutor](https://favtutor.com/articles/mc-bench-minecraft-ai-models/)). Its successor MineBench drops the code step and has models output raw JSON `{blocks:[{x,y,z,type}]}`, with a teaser top-three of GPT-5.4, "Claude 4.5" and Gemini 3 Pro and a profile page for Claude Opus 5 ([minebench.ai](https://minebench.ai/)). The consistent pattern across MC-Bench, IotA-asce and the schematic MCPs is "model emits a build program or block list; a deterministic executor places it," which is precisely the architecture the AC Worlds generator already has. The upgrade is in the executor, not the model.

## Recommended stack and migration plan for AC Worlds

The recommended stack is a vanilla datapack of tiled structure templates as the build artefact, a local Paper 26.3 server with RCON on localhost as the control channel, and a thin Python MCP bridge as Claude Code's interface, with WorldEdit 7.4.6 Fabric kept installed on the client for interactive fixes. This keeps AC Worlds reproducible by anyone who drops the datapack into a world, gives Claude a blind-free channel with text responses, and avoids every component that is version-locked at 26.1.

Two decisions are worth stating explicitly. Moving Animus onto a local server is not giving up singleplayer in any meaningful sense: the client still connects alone to `localhost`, the world still lives on the same Mac, and the only new cost is that the client and server must not open the same folder at once; if the user wants to keep the original `saves/Animus` as the canonical copy, copy the server world back after a build session, remembering that 26.1 made world upgrades one-way and that the save layout now lives under `dimensions/` and `players/` ([PaperMC news: 26.1](https://papermc.io/news/26-1); [Minecraft Wiki: Java Edition level format](https://minecraft.wiki/w/Java_Edition_level_format)). And the template tiler should be built before the RCON channel, not after, because it pays off in both worlds: in singleplayer it reduces the keystroke pipeline to two typed commands (`/reload` and `/function acworlds:build_all`), and over RCON it keeps every command far below the 1446-byte limit.

Three open questions should be settled by five-minute tests rather than more reading. Whether `/place template` on 26.3 accepts a datapack template larger than 48 per axis (the structure-block cap is a UI constraint, and server APIs create bigger templates) would remove tiling altogether if true; the safe default is to tile. Whether `/gamerule` still accepts camelCase as an alias on 26.3 (no source says so, and the existence of a mod to restore the old names implies not) determines how aggressively to scrub older functions. And whether WorldAPI has a 26.3 build (its repo and Modrinth page were unreachable) decides if MairwunNx's 51-tool MCP server with undo is a real option for the singleplayer client; if it is, it becomes the second-ranked channel after RCON.

## Conclusion

The research reframes the problem: the AC Worlds pipeline was never wrong in architecture, only in encoding and transport. Generating builds offline in Python and handing them to a deterministic in-game executor is exactly what MC-Bench, the schematic MCP servers and the best community Claude builders do; the difference is that they ship a compact artefact (a template, a `.schem`, a build script) rather than 151,000 individual commands, and they talk to the game over a socket rather than a keyboard. Mojang's 26.x cadence, now quarterly with registry-style renames landing in snapshots, also changes the maintenance posture: anything that joins the game as a fake player (Mineflayer, Mindcraft, most MCP servers) will lag each drop by months, while anything that speaks commands over RCON or writes vanilla formats survives drops with at most a rename, as the `maxCommandChainLength` incident just demonstrated.

The implication going forward is to invest in the vanilla and protocol-stable layers and treat everything else as disposable. A template-tiling datapack plus an RCON bridge is a small amount of code that will outlive Mineflayer's next three protocol catch-ups, and once Claude Code has a `place_model` tool with a `probe_block` to verify it, the interesting work shifts from importing the 119 landmarks to letting Claude iterate on them in place.
